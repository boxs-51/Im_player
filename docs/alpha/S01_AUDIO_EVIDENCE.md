## Multiple-underflow correlation (2026-10-21)
A trace may contain several SDL underflows: a startup/paused/incomplete marker followed by a mid-playback event. The initial analyzer only examined the earliest marker and could miss later matching evidence. A frozen RED-first set of seven tests was committed at `ca0c8f0b983da3dc37dde406f32b94859139f262`. [GitHub S01 run #39579408507](https://github.com/boxs-51/Im_player/actions/runs/39579408507) reproduced 4 FAIL + 2 ERROR out of 24 tests on **both Ubuntu and Windows**; the 17 preexisting tests remained PASS. The remaining additional single-event control also PASSed.

The implementation now evaluates underflows in ascending `t_us`, retaining same-load/generation guards and paused/idle exclusion, and selects the **earliest correlated event** rather than the first logged underflow or largest observed gap in the whole trace. Its JSON adds `selected_underflow_t_us` (null when none) and `examined_underflow_count`, while preserving `underflow_count`, `root_cause=UNKNOWN` and `audible_output_verified=false`. An unmatched event never certifies normal audio; a matched marker never isolates MPV/source vs pipe/capture cause. Physical affected-media Debug/Release playback remains NOT_RUN and S02 remains HOLD.

## Shutdown lifecycle / incomplete playback-state guard — 2026-10-21

The Windows implementation emits `[Lifecycle] phase=STOP component=...` for `PlayerSession`, `AudioOutputWorker`, `AudioProcessor` and `AudioCaptureManager` into the same evidence file as `[AUDIO-TELEMETRY]`. However `LifecycleEvidence::Emit` supplies neither `t_us` nor `load_id`; cross-thread append order is not a reliable proof of exact causal ordering or session identity.

At the RED-first test commit `fac9fb1d59f1c69d412f3b6d5033bee31bbf6a80`, [GitHub S01 run #39585947150](https://github.com/boxs-51/Im_player/actions/runs/39585947150) reproduced exactly **3 FAIL + 4 ERROR, 24/31 PASS** on Ubuntu and Windows without changing the pre-existing 24 tests. These tests establish risks of false attribution after STOP, partial playback state and permissive `--require-reproduction`.

The new analyzer excludes underflow markers logged **after** one of the above STOP records (conservative fail-closed in shared trace), distinguishes `playback_context_verified=true` only when **all five** source-emitted playback flags (`paused`, `core_idle`, `idle_active`, `seeking`, `pause_for_cache`) are explicitly zero, and prefers a later correlated candidate with complete active flags over an earlier weak candidate. Incomplete state may still yield a *marker observation* for legacy investigation, but the output marks `playback_context=UNKNOWN` and the CLI `--require-reproduction` refuses to pass it. Event/marker association is not causality, and these flags/STOP markers are not a trusted user-heard audio oracle.

**Unresolved:** lifecycle STOP has no per-load identity and log append order across threads may race. The conservative STOP handling can produce false negatives for interleaved sessions, but must not be portrayed as a complete physical shutdown classifier. No C++ production instrumentation or host playback was added; PR #62 remains DRAFT, S02 HOLD, exact-media physical Debug/Release NOT_RUN.
